5. Points précis à ne pas confondre pendant la correction

Retours

L’ordre réel de _aggregate_frames est démontré à la fois par le return et par son déballage dans _build_result / _validate_result_envelope :

parcels, assessments = _aggregate_frames(...)
# return: (GeoDataFrame, DataFrame)

Le writer de test renvoie trois éléments structurés :

manifest_path, paths, manifest = _write_artifacts(...)
# Path ; dict[str, Path] ; dict[str, object]

Ne pas changer ces signatures ou leurs appels pour corriger la prose.

Callback interdit versus spy déléguant

Le callback counted à l’intérieur du test de JSON strict est une sentinelle :

artifact_reads += 1
raise AssertionError("Artifact read preceded strict manifest validation")

Le callback counted_bytes de ce même test délègue à Path.read_bytes. Ils utilisent le même compteur, pas deux compteurs indépendants. La sentinelle ne délègue à aucun reader enregistré. Ne pas confondre ce montage avec inspect_read du test de remplacement physique, qui délègue réellement.

Assertions et appels

Un test utilisant _build_from_relations exécute les gardes du builder privé, mais n’exécute pas automatiquement _validate_result_envelope. Indiquer un appel d’enveloppe uniquement si le chemin du test le contient. Ne pas enlever les bonnes limites sur l’adapter legacy ou les objets globaux pour remplacer ces explications par des affirmations plus générales.

L’absence d’une assertion dans un test ne signifie pas que le comportement n’est jamais testé ailleurs. Pour les IDs triés, une référence au test qui les affirme réellement est permise, mais ne pas transférer ses assertions dans le test des deux rôles sélectionnés.

Métadonnées et erreurs

_validate_record calcule d’abord des valeurs locales figées, valide, puis les affecte. Ne pas parler d’une mutation du modèle avant ces gardes.

Pour les helpers levant ValueError, nommer cette exception locale. Expliquer séparément la conversion par Pydantic ou les wrappers publics lorsque pertinente. Le simple héritage de l’erreur applicative depuis ValueError ne rend pas tous les ValueError des erreurs applicatives spécifiques.

_read_verified_artifact possède des erreurs applicatives explicites pour ses comparaisons ; il ne possède pas un try/except global couvrant read_bytes et Parquet. Le loader public apporte cette traduction. Aucune modification du comportement d’erreur n’est autorisée ici.
